Deep-dive study guide

Dunder methods, class decorators, and the machinery behind Python objects.

This guide is deliberately more detailed than the quiz. It explains what Python is doing underneath ordinary-looking syntax, with runnable examples and special attention to attribute-access “trapping”: the hooks Python invokes when code reads, writes, deletes, or inspects attributes.

Core mental model: Python syntax such as len(x), x + y, with x, x.name, and x() often translates into protocol calls involving special methods. Learn the protocol, not just the spelling of the method.

1. What does “dunder” mean?

Dunder means “double underscore”. A Python special method normally has the form __name__. These names are part of Python's data model: they let your class participate in built-in language operations.

For example, when you write len(cart), Python looks for the object's length protocol, implemented by __len__. When you write cart[0], Python uses __getitem__. When you write print(cart), Python eventually asks for a string representation through __str__.

Do not call dunder methods randomly. Usually write len(x), x + y, str(x), x[i], etc. Let Python invoke the protocol. Direct calls are useful for learning and for some advanced implementations.

2. Object lifecycle: __new__, __init__, __del__

__new__ — create the instance

__new__ is responsible for creating and returning the instance. It receives the class as cls, not an existing instance. It runs before __init__.

class User:
    def __new__(cls, name):
        print("1. __new__")
        obj = super().__new__(cls)
        return obj

    def __init__(self, name):
        print("2. __init__")
        self.name = name

u = User("Harsh")
# 1. __new__
# 2. __init__

__init__ — initialize the instance

__init__ configures an object that has already been created. It should return None. It is not the allocator.

__del__ — finalization hook

__del__ may run when an object is being finalized, but it is not a reliable general-purpose resource manager. For files, locks, database connections, etc., prefer context managers with with.

Exam distinction: __new__ creates/returns the object; __init__ initializes it. If __new__ returns an object that is not an instance of the class, normal __init__ handling can be skipped.

3. Representation and comparison

__str__

Human-friendly representation used by str(x) and normally by print(x).

__repr__

Developer-oriented representation used by repr(x) and often containers. A good repr helps debugging.

__format__

Controls formatted output such as f"{x:.2f}".

__bytes__

Defines conversion through bytes(x).

class Money:
    def __init__(self, amount):
        self.amount = amount

    def __str__(self):
        return f"₹{self.amount:.2f}"

    def __repr__(self):
        return f"Money({self.amount!r})"

m = Money(125.5)
print(m)        # ₹125.50
print(repr(m))  # Money(125.5)

__hash__ is related to equality. Objects used as dictionary keys or set members need a stable hash/equality relationship. Mutable objects that change the fields used for equality should generally not be hashable.

Reflected operators

Methods such as __radd__, __rsub__, and __rmul__ give the right-hand object a chance to handle an operation when appropriate.

class Vector:
    def __init__(self, x):
        self.x = x
    def __add__(self, other):
        return Vector(self.x + other.x)
    def __repr__(self):
        return f"Vector({self.x})"

print(Vector(2) + Vector(3))  # Vector(5)

Other protocols include bitwise operators (__and__, __or__, __xor__, shifts) and matrix multiplication (__matmul__, __rmatmul__).

5. Container and collection protocols

__len__

Called by len(x). Must return a non-negative integer.

__getitem__

Handles x[key], including integer and slice keys.

__setitem__

Handles x[key] = value.

__delitem__

Handles del x[key].

__contains__

Handles membership testing with item in x.

__iter__ / __next__

Define iteration and iterator advancement.

class Playlist:
    def __init__(self, songs):
        self.songs = songs
    def __len__(self):
        return len(self.songs)
    def __getitem__(self, index):
        return self.songs[index]
    def __contains__(self, song):
        return song in self.songs

p = Playlist(["A", "B", "C"])
print(len(p))      # 3
print(p[1])        # B
print("C" in p)   # True
print(p[0:2])      # ['A', 'B']

Other useful protocols include __reversed__ for reversed(x), __missing__ for subclasses of dict, and __index__ for objects that can act as integer indices in low-level operations.

6. Iteration, calling, truth testing, and async

Iteration

An iterable normally supplies __iter__. An iterator supplies __next__ and returns itself from __iter__. When it is exhausted, __next__ raises StopIteration.

class CountUp:
    def __init__(self, stop):
        self.current = 0
        self.stop = stop
    def __iter__(self):
        return self
    def __next__(self):
        if self.current >= self.stop:
            raise StopIteration
        self.current += 1
        return self.current

for n in CountUp(3):
    print(n)  # 1, 2, 3

__call__ — make an object callable

class Multiplier:
    def __init__(self, factor):
        self.factor = factor
    def __call__(self, value):
        return value * self.factor

times3 = Multiplier(3)
print(times3(10))  # 30

__bool__

Controls truth testing such as if obj: and bool(obj). If __bool__ is absent, Python can fall back to __len__.

Async protocols

__await__ participates in await x. Async iteration uses __aiter__ and __anext__, with async for. Async context managers use __aenter__ and __aexit__.

7. Context managers

The expression with resource as value: uses the context-manager protocol.

class ManagedFile:
    def __init__(self, path, mode):
        self.path = path
        self.mode = mode
    def __enter__(self):
        self.file = open(self.path, self.mode)
        return self.file
    def __exit__(self, exc_type, exc_value, traceback):
        self.file.close()
        return False

with ManagedFile("notes.txt", "w") as f:
    f.write("hello")

__enter__ runs when entering the block. __exit__ runs when leaving it, even if an exception occurs. Returning True from __exit__ suppresses the exception; returning False or None lets it propagate.

Why this matters: this protocol is why with open(...) can reliably close a file. It is a language-level cleanup pattern, not merely a convenience syntax.

8. Attribute “trapping” in detail

“Trapping” is a useful way to think about intercepting normal attribute operations. Instead of Python simply reading or writing a value, your class can insert logic into the operation.

obj.name
attribute hook
validation / lookup / logging
value

__getattribute__ — trap every attribute read

This is the most important hook. Python calls it for essentially every normal instance attribute lookup. That includes attempts to access methods. Because it sees everything, careless implementations can recurse forever.

class Traced:
    def __init__(self):
        self.name = "Harsh"

    def __getattribute__(self, name):
        print("READ:", name)
        return object.__getattribute__(self, name)

x = Traced()
print(x.name)
# READ: name
# Harsh

Notice the use of object.__getattribute__(self, name). Writing return self.name inside the hook would call __getattribute__ again, which calls it again, and so on.

__getattr__ — trap only missing attributes

__getattr__ is different. Python invokes it after normal lookup fails with AttributeError.

class Settings:
    def __init__(self):
        self.theme = "dark"

    def __getattr__(self, name):
        return f"default for {name}"

s = Settings()
print(s.theme)      # dark
print(s.language)   # default for language
Key difference: __getattribute__ sees successful and unsuccessful reads. __getattr__ is the fallback for a missing attribute.

__setattr__ — trap assignments

class User:
    def __setattr__(self, name, value):
        if name == "age" and value < 0:
            raise ValueError("age cannot be negative")
        object.__setattr__(self, name, value)

u = User()
u.age = 20
# u.age = -1  -> ValueError

Again, use object.__setattr__ (or super().__setattr__) to perform the actual assignment. Writing self.name = value inside __setattr__ would recursively invoke the hook.

__delattr__ — trap deletion

class Protected:
    def __init__(self):
        self.token = "secret"
    def __delattr__(self, name):
        if name == "token":
            raise AttributeError("token cannot be deleted")
        object.__delattr__(self, name)

__dir__ — customize introspection

dir(obj) normally asks the object for names it considers useful. A custom __dir__ can expose a curated list, although it should be used carefully because tools and developers expect dir() to be informative.

Complete trapping example

class Observable:
    def __init__(self):
        object.__setattr__(self, "_data", {})

    def __getattribute__(self, name):
        if name == "_data":
            return object.__getattribute__(self, name)
        data = object.__getattribute__(self, "_data")
        if name in data:
            print("GET", name)
            return data[name]
        return object.__getattribute__(self, name)

    def __setattr__(self, name, value):
        print("SET", name, value)
        data = object.__getattribute__(self, "_data")
        data[name] = value

x = Observable()
x.score = 42
print(x.score)
# SET score 42
# GET score
# 42

This is conceptually similar to a proxy: ordinary syntax is preserved while the class inserts behavior around the operation. The same idea appears in validation frameworks, lazy attributes, ORMs, observable objects, configuration objects, and mocking libraries.

Do not overuse trapping. It is powerful but easy to make confusing. Prefer normal attributes, properties, or descriptors when they express the intent more clearly.

9. Descriptors: the deeper attribute machinery

A descriptor is an object that defines methods such as __get__, __set__, or __delete__. Descriptors are a major part of how Python implements properties, methods, and many framework APIs.

class Positive:
    def __set_name__(self, owner, name):
        self.name = name
    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__.get(self.name)
    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError("must be positive")
        instance.__dict__[self.name] = value

class Product:
    price = Positive()

p = Product()
p.price = 10
print(p.price)  # 10

Properties are built with descriptor machinery. This is why @property can make a method behave like an attribute.

Why methods are descriptors

A function defined on a class implements descriptor behavior. When you access obj.method, Python produces a bound method with obj supplied as the first argument. That is the underlying reason self appears automatically.

class Greeter:
    def hello(self):
        return "hi"

g = Greeter()
# Greeter.hello is the function stored on the class.
# g.hello is a bound method that remembers g as self.
Other descriptor hooks include __set_name__, which lets a descriptor learn the attribute name assigned to it, and __delete__ for deletion.

10. Class decorators

A class decorator is a callable applied to a class immediately after the class statement creates it.

@decorate
class User:
    pass

# roughly means:
class User:
    pass
User = decorate(User)

The decorator receives the class object and may return the same class, a modified class, or even a replacement object.

Simple example

def add_debug_flag(cls):
    cls.debug = True
    return cls

@add_debug_flag
class Service:
    pass

print(Service.debug)  # True

Class decorator that wraps methods

def add_logging(cls):
    original = cls.run
    def run(self, *args, **kwargs):
        print("running")
        return original(self, *args, **kwargs)
    cls.run = run
    return cls

@add_logging
class Job:
    def run(self):
        return "done"

print(Job().run())
# running
# done
Class decorator vs metaclass: a class decorator modifies a class after the class object has been created. A metaclass controls class creation itself. For many practical customizations, a class decorator is simpler and easier to reason about.

11. Important built-in decorators

@classmethod

The decorated method receives the class as its first argument, conventionally called cls. It is useful for alternate constructors and class-level operations.

class User:
    def __init__(self, name):
        self.name = name

    @classmethod
    def from_email(cls, email):
        name = email.split("@")[0]
        return cls(name)

u = User.from_email("harsh@example.com")

@staticmethod

No self or cls is automatically supplied. It is a normal function stored in the class namespace for logical grouping.

class Math:
    @staticmethod
    def clamp(value, low, high):
        return max(low, min(value, high))

print(Math.clamp(12, 0, 10))  # 10

@property, @x.setter, @x.deleter

These expose method-backed behavior using attribute syntax.

class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("negative balance")
        self._balance = value

    @balance.deleter
    def balance(self):
        self._balance = 0

@abstractmethod

Used with ABC to define an interface/contract. A concrete subclass must implement the abstract method before it can be instantiated.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side ** 2

@dataclass

From the standard library, dataclasses.dataclass can generate common methods such as an initializer and representations, and optionally equality and ordering depending on its arguments.

from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(2, 3)
print(p)  # Point(x=2, y=3)

Other useful class decorators

@functools.total_ordering

Given equality plus one ordering operation, supplies the other ordering methods.

@typing.final

Marks a class or method as not intended to be overridden. It is primarily a static type-checking signal, not a runtime enforcement mechanism.

@typing.override

Marks a method as intentionally overriding a base-class method. Type checkers can verify the relationship.

@functools.cached_property

Computes a property once and caches the result on the instance, useful for expensive derived values.

12. Class creation and metaclasses

Everything is an object in Python, including classes. A class is itself an instance of a metaclass. By default, most user-defined classes use type as their metaclass.

class User:
    pass

print(type(User))  # 
print(type(User()) )  #

A custom metaclass can intercept class creation. The key hooks are __prepare__, __new__, and __init__ on the metaclass.

class Registry(type):
    registry = {}
    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        mcls.registry[name] = cls
        return cls

class Service(metaclass=Registry):
    pass

print(Registry.registry["Service"] is Service)  # True

Use metaclasses only when the problem genuinely concerns class creation. If you only need to add behavior to an already-created class, a class decorator is usually easier.
